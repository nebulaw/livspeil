# CLAUDE.md

Guidance for AI coding agents working in this repository.

## What this is
Livspeil: an Arch-based OS whose desktop is a user-authored scene (Dream Mode edits it, Live Mode uses it), built from Charms (typed-port node graphs). This repo contains the Phase 0 headless kernel (`livspeil-node-api`, `-graph`, `-params`, `-doc`, `-cmd`, `-nodes-core`, `-script`, `-wasm-host`, `-cli`) and the Phase 1 UI crates (`crates/livspeil-ui-*`: core, layout, theme, render, text, paint, widgets, a11y, shot, host-winit; see `README.md`). Design specs are in `specs/`.

## Hard rules
- The kernel crates never depend on Bevy, wgpu, Wayland, or any UI crate. Keep them headless and cross-platform (macOS and Linux).
- Livspeil UI crates (`crates/livspeil-ui-*`) may depend on wgpu (and later winit, AccessKit, text crates); kernel crates must not depend on them. UI crates must not depend on GPL kernel crates.
- Every file needs SPDX headers (see existing files) or an entry in `REUSE.toml`. `crates/livspeil-node-api` and every `crates/livspeil-ui-*` crate are MPL-2.0 (decision D33); everything else in code is GPL-3.0-or-later; docs are CC-BY-4.0.
- New dependencies must be license-compatible (see `deny.toml`). Do not add copyleft-incompatible or source-available code.
- `unsafe` is forbidden by workspace lint. Panics must not cross node boundaries.
- Nodes are deterministic pure functions of inputs, params, time (if flagged) and seeded RNG.
- The project does not use DCO sign-offs. Do not add `Signed-off-by` trailers. Keep `Co-Authored-By` trailers.
- Do not commit secrets or edit generated license texts in `LICENSES/`.

## Before you finish any task
Run `cargo xtask check`. It must pass: `cargo fmt`, `cargo clippy -D warnings`, tests, and (if installed) `cargo deny check` and `reuse lint`.

## One node per task
A node is an implementation (Rust `NodeSpec` + `cook`, registered in `register_all`), a spec file `crates/livspeil-nodes-core/specs/<id>.node.toml` (generated by `cargo xtask node-specs`; you add `description` and `[[tests]]`), and golden cases. Keep tasks small and reviewable. Workflow: `CONTRIBUTING.md` ("Adding a node"); spec format and node index: `docs/nodes.md`.

## Conventions
- Rust edition 2024, stable toolchain (`rust-toolchain.toml`).
- Golden tests use `livspeil-testkit`; refresh with `UPDATE_GOLDEN=1` and review the diff.
- Error handling: typed errors in libraries, no `unwrap` outside tests.
